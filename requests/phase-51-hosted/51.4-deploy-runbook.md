# 51.4 — First Railway Deploy Runbook

Justin presses every button in this file; agents are locked out of deploys by
design. Prereqs from the legwork list: GitHub OAuth app (can point at the
railway.app domain as an interim), Railway account. Domains can come later.

## 1. Create the project
1. railway.app → New Project → **Deploy from GitHub repo** → pick the
   TenSixtyThree repo (currently `JustPinero/tensixtythree-app`).
2. Railway reads `railway.json` from the repo root — build, preDeploy
   (`prisma db push`), start (`pnpm start:hosted`), and the `/api/health`
   healthcheck are already configured. Don't hand-edit these in the UI.

## 2. Attach Postgres
1. In the project canvas: **Create → Database → PostgreSQL**.
2. On the app service → Variables → add `DATABASE_URL` referencing the
   database: `${{Postgres.DATABASE_URL}}`.

## 3. Set the environment
Source of truth: `lib/env-manifest.ts` (hosted-required rows). Set on the app
service:

| Variable | Value |
|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (step 2) |
| `ANTHROPIC_API_KEY` | from 1Password → Cascade → Cascade Runtime |
| `BETTER_AUTH_SECRET` | fresh `openssl rand -base64 32` — do NOT reuse local |
| `BETTER_AUTH_URL` | `https://<app>.up.railway.app` (Settings → Networking → Generate Domain first) |
| `AUTH_REQUIRED` | `true` |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | from the OAuth app (legwork item 2) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | optional, when legwork item 3 is done |

Interim OAuth note: until tensixtythree.com exists, the GitHub OAuth app's
callback must be `https://<app>.up.railway.app/api/auth/callback/github`.
Create a separate prod OAuth app for this; keep the localhost one for dev.

## 4. First deploy
1. Deployments → Deploy (or push to main; auto-deploy defaults on).
2. Watch: build → preDeploy `prisma db push` (creates the schema) → start →
   healthcheck `/api/health` must go green.

## 5. Post-deploy checks
1. `https://<app>.up.railway.app/api/health` → expect
   `{"status":"ok","db":"up","missingEnv":[],...}`. Anything in `missingEnv`
   is a variable you skipped in step 3 — the payload is self-diagnosing.
2. `/signin` → Continue with GitHub → full OAuth round-trip lands you in the
   dashboard.
3. Expected degradation (by architecture, not bugs): fleet health scans,
   dispatching, and hook installs need the operator machine's filesystem —
   those panels will be empty/inert on the hosted instance until Phase 52
   (cloud runners) or the local-runner bridge.

## 6. When the domains land
1. Railway → Settings → Networking → Custom Domain → `app.tensixtythree.com`
   (CNAME at GoDaddy as instructed by Railway).
2. Update `BETTER_AUTH_URL` to the custom domain; update the GitHub/Google
   OAuth callback URLs to match. Redeploy.
3. 301 `10-63.com` → `tensixtythree.com` at GoDaddy (domain forwarding).

## Known debt (logged in audits/debt.md)
- Schema sync in prod uses `prisma db push` (project convention, no migrations
  dir). Fine while the schema is young and single-instance; convert to
  `prisma migrate` before there is production data we can't regenerate.
