# 51.4 — Railway deploy prep (hosted control plane)

## Goal
Everything needed for the first hosted deploy of TenSixtyThree on Railway,
short of pressing the deploy button (that is Justin's move, by design —
agents stay locked out of `railway up`/`--prod`).

## Context
- 51.1 gave us Postgres, 51.2 Better Auth, 51.3 Teams-on-org. The app boots
  hosted-shaped but has no deploy config, no health endpoint, and no
  machine-checkable definition of "which env vars must exist in production."
- Architecture: hosted control plane + local runners. Filesystem-dependent
  features (health scans of PROJECTS_DIR, dispatcher shell-outs) degrade on
  the hosted instance; that is expected and documented, not fixed here.
- Blocked externally on: domains (tensixtythree.com), GitHub/Google OAuth
  apps — tracked on Justin's legwork list. Deploy can go out on the
  `*.up.railway.app` domain with GitHub OAuth pointed at it as an interim.

## Acceptance criteria
- **AC1 — env manifest**: `lib/env-manifest.ts` declares every env var the app
  reads, tagged `hosted-required` | `hosted-optional` | `local-only`, with a
  description. `validateHostedEnv(env)` returns `{ ok, missing, warnings }`:
  missing = hosted-required vars that are absent/empty; warning (not failure)
  when `AUTH_REQUIRED` is not `"true"` on a hosted instance.
- **AC2 — health endpoint**: `GET /api/health` returns 200
  `{ status: "ok", db: "up" }` when Postgres answers `SELECT 1`, and 503
  `{ status: "degraded", db: "down" }` when it does not. Response includes
  `missingEnv` from the manifest so a bad deploy is self-diagnosing. Endpoint
  is exempt from auth (Railway healthcheck probes it anonymously).
- **AC3 — Railway config-as-code**: `railway.json` with build via pnpm,
  `preDeployCommand` running `prisma db push`, `healthcheckPath: /api/health`,
  restart policy on failure. `start:hosted` script in package.json that does
  NOT wrap `op run` (Railway injects env directly).
- **AC4 — runbook**: `requests/phase-51-hosted/51.4-deploy-runbook.md` — exact
  click-path for Justin: create project, attach Postgres, paste env vars
  (table generated from the manifest), first deploy, post-deploy checks,
  flipping AUTH_REQUIRED, custom domain step for when tensixtythree.com lands.

## Tests to write (Red first)
- `lib/env-manifest.test.ts`: full hosted env passes; each missing
  hosted-required var is reported by name; local-only vars never required;
  AUTH_REQUIRED!=true yields warning not failure; every var read by the app
  (grep inventory 2026-08-06) appears in the manifest.
- `lib/health-check.test.ts`: rig prisma → `{ status: "ok", db: "up" }`;
  stub prisma whose `$queryRaw` rejects → `{ status: "degraded", db: "down" }`.
