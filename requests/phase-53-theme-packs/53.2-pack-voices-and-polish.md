# 53.2 — Pack voices, theme-aware animation, card thumbnails

## Why
Justin (2026-09-04): "keep running with the other themes... I want to get
every feature in we can." The open per-theme-voices question is answered YES.
Also: the portrait talking animation still pulses hardcoded cyberpunk cyan
under every theme, and the settings cards don't show the face you're buying.

## Scope
1. **Per-theme voice defaults** — `ThemePersona` gains
   `voice: { rate: number; pitch: number; preferredVoices: string[] }`.
   `applyThemePack` (under the existing persona-pristine gate) also applies
   voiceRate/voicePitch, and when `speechSynthesis` is available picks the
   first installed voice whose name matches a `preferredVoices` substring
   (case-insensitive) for voiceURI; no match → voiceURI untouched. It never
   flips `voiceEnabled` — speaking stays opt-in.
2. **Theme-aware talking pulse** — the `delamain-talk` keyframes swap their
   hardcoded `rgba(65,166,181,…)` glows for `var(--cyan-glow)` so the pulse
   matches every theme's accent.
3. **Settings card thumbnails** — each theme card renders the pack's idle
   portrait via `<Portrait/>` beside the swatches (SVG fallback covers
   pre-portrait installs).

## Acceptance criteria → tests
- AC1 every pack has voice with rate/pitch in (0, 2] and a preferredVoices
  array → theme-registry.test.ts
- AC2 pristine apply sets voiceRate/voicePitch; matching installed voice
  sets voiceURI; no match leaves voiceURI; customized persona leaves all
  voice fields; voiceEnabled never flipped → theme-pack-apply.test.ts
- AC3 delamain-talk keyframes use var(--cyan-glow), no hardcoded
  65,166,181 rgba inside the keyframes → theme-css.test.ts
- AC4 card thumbnail is a thin registry map (tsc/lint; no new logic)
