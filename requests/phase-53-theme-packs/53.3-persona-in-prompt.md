# 53.3 — Personas reach the model

## Why
Personas are cosmetics today: `personality` and `getOverseerName` have zero
consumers, and the Overseer chat sends only messages + sessionDate. Picking
Console should make the assistant ACTUALLY terse; Curator actually scholarly.
This is the feature that makes theme packs real.

## Scope
1. `lib/persona-prompt.ts` — `buildPersonaBlock({name, personality})`:
   pure, returns "" when there's nothing to say; sanitizes untrusted
   localStorage-sourced input (coerce to string, trim, strip control chars,
   cap name at 60 chars and personality at 500); emits a `# Persona` block
   to APPEND to the base system prompt (base prompt untouched — its snapshot
   test stays green; appending keeps the cached prefix stable).
2. `app/api/overseer/chat/route.ts` — accept optional `body.persona`,
   append `buildPersonaBlock` output to TOOL_PATH_SYSTEM_PROMPT.
3. `app/components/overseer-chat.tsx` — send
   `persona: { name, personality }` from overseer settings with each turn.

## Acceptance criteria → tests (lib/persona-prompt.test.ts)
- AC1 empty/missing/whitespace name+personality → "" (prompt unchanged)
- AC2 name only → block naming the assistant; personality only → block
  with conduct; both → both
- AC3 name capped at 60 chars, personality at 500; control chars stripped;
  non-string inputs treated as absent
- AC4 output always starts with "\n\n# Persona" when nonempty (safe append)
- AC5 route wiring: covered by tsc + existing route suite (system prompt
  is passed through as `TOOL_PATH_SYSTEM_PROMPT + block`); client wiring
  is a thin settings read (tsc/lint).
