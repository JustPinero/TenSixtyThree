# 54.1 — Lockdown: invite-only auth, enforced everywhere

## Scope
1. `lib/invite-gate.ts` — pure `decideUserCreation(input)`: allow user
   creation only when the email has a pending unexpired org Invitation, a
   pending unexpired UserInvite (new model, independent users), or is in
   the ADMIN_EMAILS bootstrap allowlist. Everything else is denied — this
   backs the `databaseHooks.user.create.before` choke point covering
   OAuth, email-code, and password paths.
2. `lib/route-guard.ts` — pure path classifier for middleware: public
   (signin, auth endpoints, health, static, demo entry later), webhook
   (own secret auth), everything else guarded. Guard decision =
   {kind: "allow" | "redirect" | "401"} from (path, hasSessionCookie,
   authRequired).
3. `middleware.ts` — optimistic gate from route-guard (cookie presence;
   real checks stay server-side); pages redirect to /signin, APIs 401.
4. Prisma: `UserInvite` model (email, token, invitedById?, expiresAt,
   acceptedAt?); Better Auth admin-plugin fields (user.role/banned/...,
   session.impersonatedBy).
5. `lib/auth.ts`: emailAndPassword enabled with disableSignUp (sign-in
   only; accounts get passwords via setPassword), emailOTP plugin
   (disableSignUp, console-logged codes until 54.2 Resend), social
   disableImplicitSignUp, admin plugin, rate-limit custom rules on OTP +
   sign-in, trustedOrigins, user.create.before → invite-gate.
6. `/api/admin/invites` — admin-only POST (create invite for an email) +
   GET (list); marks acceptedAt when consumed by the gate.
7. `/api/auth/set-password` — logged-in users create their credential
   account (server-side auth.api.setPassword); `/api/auth/has-password`
   for the "set a password" prompt. /signin gains code-entry + password
   sign-in + post-login set-password prompt.

## Acceptance criteria → tests
- AC1 invite-gate matrix: org invite pending+fresh → allow; expired/
  accepted → deny; UserInvite same; admin allowlist → allow (any state);
  unknown email → deny; case-insensitive email match → lib/invite-gate.test.ts
- AC2 route-guard matrix: public paths allow without cookie; guarded page
  without cookie → redirect; guarded API without cookie → 401; anything
  with cookie → allow; authRequired=false → allow all → lib/route-guard.test.ts
- AC3 /api/admin/invites: non-admin 403, admin creates + lists, duplicate
  pending invite for same email rejected → route rig tests
- AC4 auth config/middleware/signin wiring: tsc + validate + manual smoke
  (thin glue over tested cores).
