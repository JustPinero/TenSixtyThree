# 54.2 — Resend email + BYOK Anthropic keys

## Scope
1. `lib/email.ts` — `sendEmail({to, subject, html, text?})` via Resend's
   HTTP API (RESEND_API_KEY); no key → console-log fallback (dev/local
   keeps working); network failure → {sent:false}, never throws into auth
   flows. EMAIL_FROM env (default TenSixtyThree <auth@mail.tensixtythree.com>).
   Wire into auth.ts senders (OTP, org invite) + admin invite route.
2. `lib/crypto-box.ts` — AES-256-GCM seal/open for secrets at rest;
   ENCRYPTION_KEY env (32-byte base64). Tamper/wrong-key → null, random IV.
3. BYOK: `User.anthropicKeyEnc String?`; `lib/anthropic-key.ts`
   `resolveAnthropicKey(prisma, userId|null)` → user's decrypted key else
   env ANTHROPIC_API_KEY. Wired into overseer/project/wizard chat routes.
   `/api/account/anthropic-key` (GET hasKey, PUT set-encrypted, DELETE) +
   Settings field.
4. Env manifest: ENCRYPTION_KEY (hosted-required), RESEND_API_KEY +
   EMAIL_FROM (hosted-optional).

## AC → tests
- AC1 email: posts to Resend with bearer + payload; logs without key;
  survives fetch failure → lib/email.test.ts
- AC2 crypto: roundtrip, random IV, tamper/wrong-key → null, bad key
  config throws → lib/crypto-box.test.ts
- AC3 key resolution: stored key wins, else env, null user → env
  → lib/anthropic-key.test.ts
- AC4 route: 401 unauth; PUT stores ciphertext (≠ plaintext in DB), GET
  hasKey flips, DELETE clears → app/api/account/anthropic-key/route.test.ts
