# 54.3 — Organizations: multi-org, project sharing, typed feed

## Scope
1. `lib/orgs.ts` — session-aware org core on the existing org-plugin
   tables: `createOrg` (unique slug + owner Member), `listUserOrgs`,
   `setActiveOrg` (membership-checked; stamps session.activeOrganizationId),
   `requireMembership`.
2. Schema: `OrgPost` (typed feed: goal | objective | bug | test-request |
   note; optional project attachment) + `OrgProjectShare`
   (org ⇄ project, unique pair) with relations.
3. Routes (all session-required — org features are hosted features):
   - `/api/orgs` GET (my orgs + activeOrganizationId) / POST create
   - `/api/orgs/active` PUT switch
   - `/api/orgs/posts` GET (active org feed, newest first) / POST create
     (type-validated, optional projectId must be shared to the org)
   - `/api/orgs/projects` GET shared / POST share / DELETE unshare
4. `/team` page grows: org switcher + create, shared-projects grid with
   progress, typed feed with composer. (Existing single-team API stays
   for back-compat this slice; page consumes the new endpoints.)

## AC → tests
- AC1 createOrg: owner member with role owner, slug unique-ified;
  listUserOrgs returns only my orgs; setActiveOrg rejects non-members
  → lib/orgs.test.ts (rig)
- AC2 /api/orgs + /active: 401 sessionless; create → I'm owner; switch
  persists on the session row → route rig tests
- AC3 posts: 401 sessionless, 403 non-member, 400 bad type, project
  attachment requires an OrgProjectShare; GET ordered desc
  → route rig tests
- AC4 share/unshare: member-only, duplicate share 409, unshare clears
  → route rig tests
- AC5 /team page wiring: thin fetch/map (tsc/lint + existing page test
  conventions).
