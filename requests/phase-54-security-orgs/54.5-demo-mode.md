# 54.5 — Demo mode

## Design (research-backed)
Per-session sandbox: "Try the demo" on /signin mints an ephemeral demo
user + demo org seeded with representative content (projects flagged
isDemo, boards/tickets, milestones, typed feed posts), sets the session
cookie directly (our auth-helpers resolve bare tokens), and lands in the
app with a persistent demo banner. Choke points, not UI, prevent side
effects: demo users get canned Overseer replies (zero Anthropic spend),
no dispatches, no invites/admin, no BYOK writes. Sweep: each demo start
also deletes demo identities older than 24h (org/board/post cascades).

KNOWN DEBT [54.D1]: Project rows are global (no tenancy) — demo projects
are flagged+filtered from the main dashboard, but real project
multi-tenancy is a post-54 phase.
